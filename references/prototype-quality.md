# 原型质量规范

本文件用于约束单文件可交互 HTML 原型的生成质量。进入原型生成阶段时必须执行本规范。

## 强制生成流程

原型阶段必须按以下顺序执行：

1. 原型预期说明：说明将生成的页面、核心流程、视觉风格、交互深度和模拟逻辑。
2. 原型交互清单：列出每个页面、导航、按钮、Tab、表单、弹窗、抽屉、筛选、搜索、增删改查和动态组件的具体交互结果。
3. HTML 实现：按交互清单逐项实现，不得把主要操作入口做成无响应装饰。
4. 自检修复：按本文的验收清单检查布局、交互、动态组件和 JavaScript 风险，发现问题先修复再交付。

## 布局与视觉质量

- 使用清晰的布局结构，例如侧边栏 + 顶部栏 + 内容区、顶部导航 + 内容区、或适合产品形态的工作台布局。
- 侧边栏和内容区之间必须有明确间距或分隔线，不能让文字紧贴在一起。
- 内容区应有统一的内边距，桌面端建议不少于 24px，紧凑型后台也不应低于 16px。
- 按钮组必须有间距，横向按钮之间建议不少于 8px，纵向按钮之间建议不少于 8px。
- 表单项、卡片、表格、标题、工具栏之间应有稳定间距，避免视觉拥挤。
- 不要让文字贴边、压线、重叠、被遮挡或溢出容器。
- 页面必须有一致的字体、字号、颜色、圆角、阴影、边框、按钮样式和反馈状态。
- 同一原型中不要混用多套视觉语言。
- 响应式布局至少要保证常见桌面宽度和较窄窗口下不崩坏。

## 可点击元素规则

- 所有看起来可点击的主要元素都必须有交互结果，包括按钮、菜单项、Tab、图标按钮、列表操作、表格操作、卡片入口和节点操作。
- 如果某个按钮暂不实现，也必须给出可感知反馈，例如 toast 提示“该能力为后续扩展”，不能静默无响应。
- 主要按钮必须体现成功、失败、禁用、加载或完成等状态中的相关状态。
- 危险操作必须有确认过程，例如删除确认弹窗或二次确认提示。

## CRUD 与数据交互

- 新增：应打开弹窗、抽屉或表单页；提交后将模拟数据插入列表，并给出成功反馈。
- 查看：应打开详情区域、详情弹窗、详情页或高亮选中项。
- 编辑：应回填原数据；保存后更新列表或详情中的模拟数据。
- 删除：应要求确认；确认后从模拟数据中移除，并展示反馈。
- 搜索：应根据关键字过滤列表或卡片。
- 筛选：应根据条件更新结果，并展示当前筛选状态。
- 排序：如界面提供排序入口，点击后应改变排序结果或排序方向。
- 状态流转：如存在审批、发布、启停、归档等操作，应更新状态标签和相关操作可用性。

## Tab、导航与页面状态

- Tab 切换必须改变内容区，并更新选中状态。
- 侧边栏或顶部导航切换必须改变当前视图，并更新当前菜单高亮。
- 面包屑、返回、详情、编辑等页面路径应能形成可理解的流程。
- 弹窗、抽屉、下拉菜单必须支持打开和关闭。
- 表单必须有基础校验和错误提示，不能提交明显无效的数据。
- 空状态、加载状态、错误状态、成功反馈至少要覆盖核心流程中最容易出现的场景。

## 动态组件规范

当 PRD 或用户需求包含以下组件时，不能只画静态图，必须实现可体验的动态交互。

### 工作流编排

- 支持选择节点，并展示节点详情或配置面板。
- 支持新增节点、删除节点、编辑节点名称或属性中的至少一种核心操作。
- 支持节点状态变化或流程模拟运行，例如待执行、执行中、成功、失败。
- 如涉及连线，应能通过模拟方式展示节点关系、路径高亮或条件分支。
- 至少提供一个“运行/预览/校验流程”入口，并展示执行反馈。

### 可视化图谱

- 支持节点点击选中，并展示节点详情。
- 支持拖动画布或节点中的一种动态行为；若实现拖拽成本过高，至少实现节点高亮、关系过滤、缩放或展开收起。
- 支持按类型、状态或关键字过滤节点。
- 支持关系线高亮，帮助用户理解节点之间的连接。

### 看板与任务流

- 支持卡片详情查看。
- 支持状态切换，优先实现拖拽；如果拖拽不稳定，可以用按钮或菜单模拟移动到下一状态。
- 状态变化后必须更新卡片所在列和统计数字。

### 图表与数据看板

- 图表应使用内联 SVG、Canvas 或 HTML/CSS 实现，避免依赖外部库。
- 筛选条件变化后，图表、指标或列表应同步变化。
- 指标卡、趋势图、分布图应有 hover、选中、过滤或联动中的至少一种交互。

## 单文件 HTML 约束

- 默认只输出一个 `.html` 文件。
- HTML、CSS、JavaScript 默认内联。
- 默认不依赖后端服务、真实数据库、构建工具、包安装、外部 API 或外部 CDN。
- 可使用模拟数据、浏览器内存状态和 `localStorage`。
- 如果用户明确要求真实接口、真实登录、数据库、文件上传、支付或部署，应先说明这超出单文件原型范围，并询问是模拟还是转工程实现。

## 交付前验收清单

交付前必须逐项检查：

- 主要页面可以进入，导航和当前状态清晰。
- 主要按钮、菜单、Tab、图标按钮和操作入口点击后有反馈。
- 增删改查、搜索、筛选、排序、表单校验等核心功能可通过模拟数据体验。
- 动态组件不是静态摆设，至少具备选中、编辑、运行、过滤、拖拽、缩放、展开、连线高亮中的相关交互。
- 侧边栏和内容区没有贴在一起，按钮之间没有紧挨，文本没有贴边或重叠。
- 弹窗、抽屉、下拉菜单、toast 不遮挡关键内容，也不会超出可视区域。
- 桌面和较窄窗口下没有明显布局崩坏。
- JavaScript 中不存在明显未绑定事件、未定义变量、重复 id 导致的核心交互失败。
- 外部资源没有失效风险；如使用外部资源，已获得用户确认。
- 原型版本和 `index.md` 已更新。
